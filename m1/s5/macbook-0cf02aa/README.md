## Setup

- **Code:** [PR #23](https://github.com/SirajChokshi/lug-layout/pull/23) at `0cf02aaed46c782722d1c7d3d70c971d7c02e58a`, built with `pnpm install --frozen-lockfile`, `restore-ldraw`, the asset-pipeline `build` (bundle standard `1fd935a2278f8b65`, low `cc7a389a7a97cb3b`) and `pnpm --filter @brr/web build`, served with `pnpm --filter @brr/web preview --port 4173`.
- **Driver:** `m1/s5/scripts/s5-latency.cjs` from `siraj/m0-evidence-b86f` at `6fa5f4b994303edfda152ece1a7ab58f06375cd8`, run as `node s5-latency.cjs --api <api> --channel chrome --width 1800 --height 1000 --dpr 2 --trials 50 --sets omr:10218-1 --out <dir>`. It places one 32×32 baseplate, then for each of the four rotations runs 50 trials of place, select, R and Delete, so each API gets 200 rotations.
- **Machine:** MacBook Pro, Apple M4 Max (16 CPU cores, 40 GPU cores, 64 GB), macOS 26.6.2, Google Chrome 157.0.8103.52 (the installed Chrome, real GPU, headed), Node v26.9.0, playwright-core 1.63.0. Each sample's breakdown comes from the editor's own `#edit-state` dump (`edit-state.json`).
- **Power-mode values:** in `pmset`, 2 is High Power and 1 is Low Power.
- **Other load on the machine:** the owner was using it during the battery runs. Another Chrome (v155) was busy, the camera and audio daemons were active, and `fseventsd` was still at about 100% after the clone and build.
- **Raw outputs on the Mac:** `~/brr-s5-mac/s5-scripts/m1/s5/scripts/latency-<api>-<run>/` holds `edit-state.json`, `hud.txt`, `console.txt` and `final.png`.
