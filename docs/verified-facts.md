# Verified facts

Facts about LDraw parts, licenses, dimensions, connector poses and module standards that code or data relies on. Add rows with the `verify-ldraw-facts` skill (`.cursor/skills/verify-ldraw-facts/SKILL.md`). Never add a row from memory.

## Inputs

There is one LDraw pin, the one the bundle ships: `palette.json` `source`, which is `kulits/ldraw-parts@c70360d1c588be894997b2168c61909bc8058c4d` (`ldraw/`). That mirror is a daily, unmodified unzip of the official `complete.zip`, here library update 2026-10. LDCad connectivity comes from `palette.json` `connectivitySource`, `RolandMelkert/LDCadShadowLibrary@9b1131fb1991f8c0bfc072325e4e12f6271aba35` (CC BY-SA 4.0). It's used for verification only, and is never committed or bundled.

`pnpm --filter @brr/asset-pipeline fetch-ldraw` downloads, with the one fetcher (`src/fetch-ldraw.ts`):

- the bundle closure (palette parts plus every part the `models` reference) into `packages/test-fixtures/ldraw`;
- the closure of every part in `palette.json` `audit` into `.cache/ldraw-audit`;
- the matching LDCad patches into `.cache/ldcad-shadow`.

Every file is pinned by SHA-256 in `ldraw.lock.json`: `files` for the bundle and `audit` for the rest. `facts` re-checks those hashes and writes `docs/verified-facts/license-audit.json`; `facts --check` reports drift instead. `library.ldraw.org`, Rebrickable and the MILS site are blocked from the verification environment.

## Geometry

All geometry is measured at the bundle's pin, from the `audit` closure that `run fetch` pins, by `tools/asset-pipeline/src/verify/geometry.ts` (run through `cli.ts facts`). The full output is in `docs/verified-facts/geometry.json`. Values are **as modelled in LDraw**, in the LDraw part frame (−Y up, 1 LDU = 0.4 mm), before any y-up conversion.

Track ends are the origins of the end-sleeper sub-files listed in `tools/asset-pipeline/src/track/track-end-markers.json`, with the outward direction taken from each placement's matrix. The report checks every declared outward direction against the part's bounds (all agree), and the LDCad `traintrk` snaps against the marker origins (they coincide).

Relative poses are measured from the end with the least x, rotated so that its inward direction is +x. They're written in studs as ℤ[ζ₁₆] coefficients (c₀…c₇) of Σ cₖζᵏ, with x → Re and z → Im. A pose is **certified** under the owner's rule: certified iff residual ≤ 0.0005 LDU (half the last decimal of 3-decimal LDraw data). The residual is measured against a candidate, which is the unique coefficient vector with |c| ≤ 64 found within one unit of the file's last printed decimal; with no candidate, or more than one, there is nothing to certify. `geometry.json` records coefficients only for certified ends; for the others it records the search result and `null`.

The same command writes two LDraw scenes. `docs/verified-facts/scenes/switch-then-reversed-curve.ldr` places its parts from the measured track-end poses, with placement rotations snapped to the 11.25° grid. `docs/verified-facts/scenes/road-baseplates.ldr` abuts the plates edge to edge using their measured body extents (`baseplates[].zExtent`). Both are listed under `palette.json` `models`, so the bundle build bakes them like any model, and the app renders them at `/?model=switch-then-reversed-curve` and `/?model=road-baseplates`. The screenshots in `docs/verified-facts/evidence/` were taken there with the WebGL2 backend. Parts use colour 16 (LDConfig main colour), because no produced colour is claimed.
